# Specification: Lotto Public Result Archive API

## Summary

Create `lotto_result_archives` as a dedicated read model for historical lottery result statistics. Mirror data from resulted draws into the archive, fill gaps from external sources, and expose via FrontendApi public endpoints with throttle and cache.

## Context

1168lot is a lottery platform handling the full lifecycle: betting, draw management, result calculation, settlement. Currently there is no optimized read model for public historical result queries — FrontendApi would need to query `lotto_draws` directly. The archive provides a decoupled, cacheable read path without impacting operational draw tables.

## User Story

As a frontend platform, I want a stable historical lottery result read model so that public result APIs can serve fast, cacheable, and decoupled historical data without impacting settlement and operational draw tables.

- [ ] `lotto_result_archives` และ `lotto_result_archive_logs` tables with correct schema
- [ ] Normalizer: mapping `lotto_draws` + bet settings → archive format (market_code, draw_date, draw_key, result_set)

## Technical Notes

- `result_set` = `array<string>` only — no objects, no nested keys, no display metadata
- Idempotent writer: same hash = skip (no correction_count increment), different hash = correction
- Use `DB::transaction()` + `lockForUpdate()` — NOT plain `->upsert()`
- Pagination at draw_date group level, not archive row level
- Log FK: `ON DELETE SET NULL` — audit trail survives archive deletion
- External fill MUST NOT overwrite `internal_mirror` by default; enforced in Writer
- Reconcile `--fix` requires `--market`, `--from`, `--to`, `--yes`; max 366 day range
- API date range: both-or-neither from/to, max 366 days, default 365, single param = 422
- `source_info_json` validation required for `external_fetch`
- Market disabled → historical still readable (archive = record, not live betting)
- Cache invalidation on every archive write/correction
